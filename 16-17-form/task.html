Практичне заняття: Робота з формами React

  • Контрольовані компоненти
  • Події форми, обробка подій (onChange, onSubmit)
  • Інтерактивні форми (умовний рендеринг)
  • Валідація введених даних
  • Різні типи даних (select, checkbox, radio)

Вихідні дані та Приклади коду

Цей код демонструє базові принципи роботи з формами в React. Вивчіть його перед виконанням завдань.

Приклад 1: Базовий контрольований Input ▼ 
import { useState, useId } from 'react';

function NameForm() {
  const [name, setName] = useState('');
  const id = useId();

  const handleChange = (event) => {
    setName(event.target.value);
  };

  return (
    <form onSubmit={(e) => e.preventDefault()}>
      <label htmlFor={`${id}-name`}>Ім'я:</label>
      <input id={`${id}-name`} type="text" value={name} onChange={handleChange} />
      {name && <p>Ви ввели: {name}</p>}
    </form>
  );
}
export default NameForm;
Приклад 2: Мульти-стейт форми (один об'єкт для всіх полів) ▼ 
import { useState } from 'react';

function LoginForm() {
  const [formData, setFormData] = useState({ email: '', password: '' });

  const handleChange = (e) => {
    const { name, value } = e.target;
    setFormData(prev => ({ ...prev, [name]: value }));
  };

  const handleSubmit = (event) => {
    event.preventDefault();
    console.log('Дані:', formData);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input type="email" name="email" value={formData.email} onChange={handleChange} />
      <input type="password" name="password" value={formData.password} onChange={handleChange} />
      <button type="submit">Увійти</button>
    </form>
  );
}

Практичні завдання

Завдання 1: Збір даних користувача

Базовий рівень

Чому це важливо: Це основа роботи з формами в React. Ви навчитеся зберігати дані кількох полів введення в єдиному об'єкті стану, що робить код чистим (DRY) і масштабованим.

Кроки виконання:

  1. Створіть компонент SimpleForm.
  2. Оголосіть стан formData, який є об'єктом з полями name (рядок) та age (рядок).
  3. Створіть універсальну функцію handleChange, яка буде оновлювати стан на основі атрибуту name поля вводу.
  4. Створіть функцію handleSubmit, яка скасовує стандартну поведінку браузера та виводить дані в консоль.
  5. Додайте два інпути (type="text" та type="number") і кнопку відправки у форму.
Підказка до коду (Вихідний шаблон) 
const handleChange = (e) => {
  const { name, value } = e.target;
  setFormData(prev => ({ ...prev, [name]: value }));
};
// Не забудьте додати name="age" до інпуту віку!
Візуальний результат: Картка з двома полями ("Ім'я" та "Вік") і кнопкою "Надіслати". При введенні даних і натисканні кнопки, сторінка не перезавантажується, а в консолі розробника з'являється об'єкт з введеними даними.

Завдання 2: Базова валідація при відправці

Середній рівень

Чому це важливо: Ніколи не можна довіряти даним від користувача. Валідація на стороні клієнта покращує UX, миттєво повідомляючи користувачеві про помилки без очікування відповіді від сервера.

Кроки виконання:

  1. Створіть компонент ValidationForm.
  2. Додайте стан для даних formData (полі email та password).
  3. Додайте стан для помилок errors (з такою ж структурою об'єкта, початкові значення - порожні рядки).
  4. У функції handleSubmit створіть локальний об'єкт newErrors. Перевірте: якщо email не містить символ "@", запишіть помилку "Email має містити @". Якщо пароль коротший за 6 символів — запишіть "Пароль має бути ≥ 6 символів".
  5. Оновіть стан помилок. Якщо помилок немає, виведіть дані в консоль.
  6. Під кожним інпутом додайте умовний рендеринг: показувати текст помилки, якщо вона існує у стані errors.
Підказка до умовного рендерингу 
{/* Відображення помилки під інпутом */}
{errors.email && <p className="error-text">{errors.email}</p>}
Візуальний результат: Форма авторизації. Якщо натиснути "Надіслати" з порожніми полями або неправильним форматом, форма не відправляється, а під відповідними полями з'являється червоний текст з поясненням помилки.

Завдання 3: Інтерактивна форма замовлення

Просунутий рівень

Чому це важливо: Складні форми часто вимагають умовного відображення полів (наприклад, запитати номер квартири лише якщо обрана доставка кур'єром). Також ви навчитеся обробляти різні типи інпутів: радіокнопки, селекти та чекбокси.

Кроки виконання:

  1. Створіть компонент OrderForm.
  2. Стан форми повинен включати: name (рядок), foodType (рядок, за замовчуванням 'pizza'), deliveryMethod (рядок, 'pickup'), extraCheese (булеве значення, false), sauce (рядок, 'tomato').
  3. Модифікуйте handleChange: для чекбоксів значення лежить в e.target.checked, для інших — в e.target.value. Використайте умову типу type === 'checkbox'.
  4. Додайте <select> для вибору їжі (Піца, Суші, Бургер).
  5. Додайте два <input type="radio"> для способу доставки (Самовивіз, Кур'єр). У них має бути однаковий атрибут name.
  6. Додайте чекбокс "Додатковий сир".
  7. Інтерактивність: Використовуючи умовний рендеринг ({formData.foodType === 'pizza' && (...)}), показуйте селект вибору соусу ТІЛЬКИ тоді, коли користувач обрав Піцу.
Підказка до обробника onChange 
const handleChange = (e) => {
  const { name, value, type, checked } = e.target;
  setFormData(prev => ({
    ...prev,
    [name]: type === 'checkbox' ? checked : value,
  }));
};
Візуальний результат: Динамічна форма. Коли у випадному списку обрано "Суші" або "Бургер", поле з вибором соусу зникає. Радіокнопки перемикаються коректно.

Додаткові завдання

Додаткове 1: Todo-лист (Форма + Масив)

Чому це важливо: Форми часто використовуються для створення нових записів, які потім рендеряться у вигляді списку. Це навчить вас не мутувати масиви напряму, а створювати нові списки за допомогою spread-оператора.

Кроки виконання:

  1. Створіть компонент TodoList.
  2. Окрім стану для тексту завдання та пріоритету, створіть стан для списку: const [tasks, setTasks] = useState([]).
  3. При сабміті форми створіть новий об'єкт завдання: { id: crypto.randomUUID(), text: taskText, priority: taskPriority }.
  4. Додайте це завдання до масиву tasks та очистіть поле вводу.
  5. Виведіть список завдань під формою за допомогою tasks.map(...), використовуючи унікальний id як key.
  6. Додайте кнопку "Очистити список", яка встановлюватиме стан масиву в порожній [].
Візуальний результат: Форма додавання завдання з полем тексту та вибором пріоритету. Нижче відображається маркований список доданих завдань. При додаванні форма миттєво очищається.

Додаткове 2: Реєстрація з "живою" валідацією

Чому це важливо: Реєстраційні форми у реальних проектах містять перевірки регулярними виразами (Regex) та порівняння паролів. А найкращий UX — це коли помилка зникає одразу, як тільки користувач почав вводити правильні дані.

Кроки виконання:

  1. Створіть компонент RegistrationForm (поля: ім'я, email, password, confirmPassword).
  2. Винесіть логіку валідації в окрему функцію validate(), яка повертає об'єкт з помилками.
  3. Для email використайте регулярний вираз: /^[^\s@]+@[^\s@]+\.[^\s@]+$/.
  4. Перевірте, щоб password збігався з confirmPassword.
  5. Модифікуйте handleChange: коли користувач вводить дані в поле, автоматично видаляйте повідомлення про помилку для ЦЬОГО поля з об'єкта errors.
Підказка до "живого" очищення помилок 
const handleChange = (e) => {
  const { name, value } = e.target;
  setFormData(prev => ({ ...prev, [name]: value }));
  
  // Якщо для цього поля була помилка - прибираємо її
  if (errors[name]) {
    setErrors(prev => ({ ...prev, [name]: undefined }));
  }
};
Візуальний результат: Велика форма реєстрації. Якщо відправити з помилками — вони з'являться червоним текстом. Але як тільки користувач клікне в поле і почне виправляти дані, текст помилки під цим полем одразу зникає.
